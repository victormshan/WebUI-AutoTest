## New in this version (beyond the sources)

| Change | Why (Codex) |
|---|---|
| A task without a principal has no owner (`owner_principal() -> Option`): only the administrator can access it; every write and every `/check` on its repository is refused | n20 ② (no automatic owner by time or legacy credential) |
| `/check` refuses when any running task of the repository is not the caller's, even if the caller also has one there | n20 (no borrowing, no "found mine, ignore the rest") |
| `read_admin_file`: O_NOFOLLOW, fstat on the same fd (regular, owner root or euid, no group/other write, nothing for others), directory checked; used for identity.json and the agents file | n18 F3 |
| `check_agents_file`: duplicates (after unescaping), legacy token, not in identity config, disabled, family mismatch, unknown family → refuse to start; without `--identity-config` → refuse | n18 F2, n20 ① |
| `milestones.json` `writers` (required, non-empty, unique, enabled principals); milestone write routes 403 for others, checked before admission; no HTTP admin exemption | n20 ③ |
| `admin task unowned` (read only) and `admin task assign` (dry run unless --yes; reason and expected updated_at required; first assignment only; owner and audit in one atomic task write; refuses while a service holds `state/service.lock` unless it is drained idle) | n20 assign requirements |
| `serve` holds `state/service.lock` for its whole life | the admin-write guard |
| `admin identity-from-agents`: identity.json from token files (hash of the client's trimmed token), legacy entry explicit, checked against the agents file (same token set, same families), no token printed, output created 0600 | n20 configuration migration |
| ETXTBSY retry in the fake-git environment test (only that error) | a flake seen once in the fault-injection suite |

== Version 2 (answering gate v1-1, web-gemini, REJECTED on segment 4) ==
1 (blocking, real): check_commit looked only at the first of the caller's running tasks on the
repository (init does not forbid several), so an approval under another of them was refused.
Fixed: every running task (all the caller's at that point) is searched for an unused eligible
approval of the tree; the commit is reported with the task the approval belongs to; when none
covers it the refusal names every task and picks none. New test
an_approval_under_any_of_the_callers_running_tasks_covers_the_commit. Mutant I19 (search only the
first task, take(1)) is KILLED by it (raw: the test FAILED, 20 passed / 1 failed; source restored
byte-identical, checked with cmp).
2 (non-blocking, not a defect): review_eligibility(..., true) in the commit check. The flag only
matters for the manual channel, and a manual record can only be written by the local
administrator command (HTTP refuses manual), so every stored manual record is the
administrator's; external and weak channels ignore it. The comment now says so; behaviour
unchanged.

== Version 3 (answering Codex's review of bde37f0e: VERDICT: REJECTED, two blocking items) ==
Codex's review text is kept verbatim: reviews/m2-step8-identity/v1-bde37f0e/codex-review.md,
sha256 8ded47fb52a2b6f2c8889991429878c06984f9a6ead52a70fdd25ed41c4eb119. It was not recorded in the
gate (that would have been the third rejection in a row and paused the task); the tree it rejected
is not committed.
1 (blocking): an administrator could change a task with no known owner (can_access let who.admin
through, and ensure_owner reused it). Fixed by separating reading from writing:
- can_read: the owner, or an administrator (list and show);
- can_write: only the owner, and the local administrator command (Identity.local_admin, set only by
  Identity::admin(), never over HTTP) for a task with a known owner. A task with no known owner can
  be changed by nobody; an administrator over HTTP has no write exemption at all.
  ensure_owner (every write route, review::run/submit) and /check use can_write.
Tests: nobody_writes_a_task_with_no_known_owner_not_even_an_administrator (HTTP admin and local
admin: link/record/add_review refused, nothing stored, /check refused, task unchanged),
an_old_approval_on_a_task_with_no_known_owner_is_never_borrowed (an approval already on file from
the old binary is never borrowed, by anyone), an_administrator_over_http_has_no_write_exemption_on_
another_principals_task. The earlier test that asserted the administrator passes ensure_owner on an
unowned task now asserts the opposite.
2 (blocking): admin task assign accepted a /health answer from any URL instead of holding the state.
Fixed: the health path is gone; assign --yes must take state/service.lock and holds it for the whole
write (Store::try_service_lock returns a ServiceLock; Gate::assign_owner needs it to write), so a
running service, a restarted one, or a second assignment all exclude it. The operator drains and
stops the service first. Test (real binary): assign_writes_only_while_it_holds_the_state_lock.
3 (non-blocking): CLI test for the writer check at start: serve_refuses_a_milestone_writer_that_is_
not_an_enabled_principal (real binary; a valid writer starts).
4 (non-blocking): read_admin_file checks the leaf and its direct parent only; the whole fixed path
/etc/review-gate is to be checked at deployment (RUNBOOK, still BLOCKED).
