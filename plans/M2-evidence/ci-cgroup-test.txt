# M2 step 8: the audit-runner own_cgroup test is environment-aware (m2-step8-identity v2)

Base 9978dd1f0477449ccb85fcefc31cd608fcb4b87b. Only crates/audit-runner/tests/runner.rs changes (one test).

## Why
CI (webtest) on m2-step1 has been red since 2026-10-19: own_cgroup_refuses_to_start_outside_a_service assumed the tests never run inside a systemd service cgroup. A GitHub runner runs as a service, so the child inherited a .service cgroup, got past the check, and the test timed out (runner.rs:704 Elapsed). Example: run 40167145278 on fd34eae.

## Reproduced before the fix (old test, inside a user service via systemd-run --user)
thread 'own_cgroup_refuses_to_start_outside_a_service' panicked at crates/audit-runner/tests/runner.rs:704:6: the runner started outside a service cgroup: Elapsed(())

## The fix
The test reads its own cgroup (audit_runner::cgroup_of). Outside a .service cgroup it asserts the refusal, as before. Inside one it asserts the runner got past the check (still running after 5 s, or stopped without the refusal message). It never skips. Production code unchanged.

## Both branches run
- outside (developer shell, 0::/non-systemd): ok
- inside (systemd-run --user, .../run-p...service): ok, 5.00 s
