File crates/review-gate/src/milestone/flow/tests/reverse_auth.rs; a test-only hook
runner::BEFORE_LIVENESS (cfg(test), keyed by the sender's pid so parallel tests never meet), run
after the uid check and before the sender's liveness check. The runner stand-in is a separate
python process (its own pid and credentials) that reads the request and sends a complete,
well-formed reply; mode "linger" keeps it alive until the gate closes the connection (after
authentication), mode "exit" ends it right after the reply.
- (a) expected uid = mine + 1: "the reply came from uid 1000, not the runner's 1001";
- (b) uid mine, expected cgroup /system.slice/audit-runner.service: "the reply came from cgroup
  /non-systemd, not the runner's /system.slice/audit-runner.service";
- (c) uid and cgroup the sender's own; the gate's liveness check waits (barrier) until the test
  has reaped the sender: "sender pid … is no longer running: not authenticated";
- (d) positive control, the same stand-in with the right identity, alive: authenticated, the
  audit takes effect (state Completed), the job records sender {pid, uid, cgroup}. So (a)-(c) fail
  at authentication, not at an earlier check.
Each refused case: the job records the error, the request ends Failed, nothing is resolved, and
the phase is not released after publish and archive.
In this WSL environment the test's cgroup reads "/non-systemd"; the deployment check of the real
runner's cgroup is E4's.
