# 运行手册：审核用 Gemini 网页 profile

状态：**草案**。只用于 A2；A2 没有获批前不在生产上使用。依据 `plans/A1-report.md`。

## 1. 所有权与权限
- profile **从一开始就归实际运行审核的身份所有**（`reviewgate` 系统用户），放在它的私有状态目录下（例如 `/var/lib/reviewgate/browser/gemini`），目录权限 0700。
- **不跨用户转交 profile**（例如把 administrator 下登录好的 profile 复制给 reviewgate）。
- 实现方用户（Claude 所在用户）对这个目录**没有读写权限**。
- Chrome 只通过 `--remote-debugging-pipe` 由 review-gate 进程启动，**不开调试端口**。

## 2. 首次登录（人工，一次）
1. 由用户以 `reviewgate` 身份、以**普通方式**（不带任何调试参数）启动 Chrome，打开这个 profile 和 gemini.google.com。原因：带调试参数时 Google 拒绝登录（A1 S4）。
   - 前提：`reviewgate` 能在 WSLg 桌面上显示窗口。这一点**尚未验证**（A1 S5），A2 部署前必须先验证。
2. 用户用**专门的账号**登录，确认能进入 Gemini 对话页，然后**完全退出 Chrome**（确认没有残留的 Chrome 进程，否则 profile 会被占用，Runtime 启动时报 `Launch` 错误）。
3. 只有人能做这一步。不允许脚本代为输入账号密码。

## 3. 运行阶段（自动）
- review-gate 用 pipe 加无头模式启动这个 profile，每次审核新开一个对话；碰到第 4 节的任何情况就停止。
- **频率限制（A1 补充发现）：** 25 分钟内连续 5 轮自动请求后，Google 弹出了异常流量验证页。所以网页通道**只能低频使用**（定位为 Gemini API 不可用时的回退）。具体频率上限要由 A3 实测决定，A3 之前保守设为：每小时不超过 N 次（N 由用户定），超过就报"不可用"。

## 4. 停止条件：交给人处理，不重试、不绕过
| 现象 | 识别方式 | 处理 |
|---|---|---|
| 登录失效 | 页面出现登录入口 / 跳转到 accounts.google.com | 报"通道不可用：需要重新人工登录"，按第 2 节处理 |
| 异常流量验证页 | 跳转到 `google.com/sorry/` | 报"通道不可用：被风控"；**本通道冷却**（时长由用户定），由用户人工处理 |
| 其他验证码或拦截页 | 页面上出现验证码，或输入框一直不出现 | 同上 |
| 浏览器启动失败、profile 被占用 | `Launch` 错误 | 报"不可用"，检查是否有残留的 Chrome |

以上每一种情况都**绝不能**记成审核通过；review-gate 按"不可用"处理，记录写明原因（通道回退留痕，`b5f9449`）。
